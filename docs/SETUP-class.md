# 全班使用前的準備（只有專案擁有人能做）

給擁有人。全班開始用雲端模式之前，依序做三件事：

1. 設定自己的寄信服務（A）。
2. 手動檢查學生隔離（B）。
3. 照開班流程建立班級、發邀請碼（C）。

前提：`docs/SETUP.md` 的 B 部分已做完，你已有督導帳號，網站已要求登入。

**標記說明**：標「（未證實）」的地方，是寫文件時沒有連到官方頁面核對的事實，可能已經改變。做之前請在該服務的官方頁面再看一次。

介面有英文和繁中兩種。下面先寫繁中畫面文字，括號內是英文。

## A. 在 Supabase 設定自訂 SMTP

### 為什麼要做

學生用「電郵登入連結」登入，沒有密碼。每次登入都要寄一封信。Supabase 內建的電郵服務每小時只能發很少的信。全班同一時間登入，後面的人收不到連結。

### 三個服務的比較

下表的數字全部是（未證實）。2026-11-23 寫這份文件時沒有連到官方頁面。

| | Resend | Brevo | 說明 |
|---|---|---|---|
| 免費額度 | 每月約 3,000 封、每日約 100 封（未證實） | 每日約 300 封（未證實） | 全班 30 人一次登入約 30 封，兩者都夠用。Resend 的每日上限若是 100 封，要避免一天內重複登入很多次 |
| 要不要網域 | 要。只有驗證過自己的網域，才能寄給你自己以外的人（未證實） | 不一定。可以只驗證一個寄件電郵，但寄件人用免費電郵（例如 gmail）時，容易被收件匣當成垃圾信（未證實） | 沒有網域時，Brevo 較容易起步 |
| 設定難度 | 要在網域的 DNS 加幾筆紀錄 | 驗證寄件電郵較簡單；驗證網域要加 DNS 紀錄 | |
| 建議 | 你有網域（例如 clinicmind 的網域）就選它 | 沒有網域，或想先測試，就選它 | 兩者擇一，不用兩個都設 |

我不替你選。你有沒有網域，決定答案。有網域，兩個都可以；寄件人用自己網域的信，進收件匣的機會最高。

第三個選項：**Supabase 內建服務加上提高限額**不可行。內建服務的限額是固定的，不能調高（未證實）。

### 設定前要準備的資料

不管選哪個服務，Supabase 都要下面六項：

| Supabase 欄位 | 填什麼 |
|---|---|
| Sender email | 寄件電郵。例如 `no-reply@你的網域` |
| Sender name | 寄件名稱。例如 `ClinicMind Practice` |
| Host | 服務商給的 SMTP 主機名稱 |
| Port number | 服務商給的埠號。常見是 `465` 或 `587`（未證實：以服務商頁面為準） |
| Username | 服務商給的 SMTP 帳號 |
| Password | 服務商給的 SMTP 密碼（或 API key） |

**密碼是機密。** 只貼進 Supabase 的表單。不要貼進對話、不要貼進任何文件、不要寫進 Cloudflare 的變數。

### 步驟 A1：選 Resend

1. 到 `resend.com`，用你的電郵註冊並登入。
2. 左側按 **Domains**，按 **Add Domain**，輸入你的網域，按 **Add**。
3. 畫面會列出幾筆 DNS 紀錄（類型、名稱、值）。到你買網域的網站（例如 Cloudflare、GoDaddy）的 DNS 設定頁，逐筆新增。
4. 回 Resend，按 **Verify**。狀態變成 **Verified** 才算成功。可能要等幾分鐘到幾小時（未證實）。
5. 左側按 **API Keys**，按 **Create API Key**。名稱填 `supabase-smtp`，權限選 **Sending access**，按 **Add**。
6. 畫面會顯示金鑰**一次**。複製它，直接貼進步驟 A3 的 Password 欄。
7. SMTP 資訊：Host、Port、Username 在 Resend 的文件頁「Send with SMTP」。Username 通常是 `resend`，Password 是上一步的 API key（未證實：以 Resend 頁面為準）。

### 步驟 A2：選 Brevo

1. 到 `brevo.com`，用你的電郵註冊並登入。
2. 右上角按你的帳號名稱，選 **SMTP & API**。
3. 按 **SMTP** 分頁。畫面列出 Host、Port、Login。
4. 按 **Generate a new SMTP key**，名稱填 `supabase`，按 **Generate**。
5. 複製金鑰（只顯示一次），貼進步驟 A3 的 Password 欄。
6. 驗證寄件人：選單進入 **Senders, Domains & Dedicated IPs**（未證實：選單名稱可能已改），按 **Add a sender**，輸入你想用的寄件電郵，Brevo 會寄驗證信。點信裡的連結完成驗證。
7. 有網域的話，同一頁按 **Domains** 驗證網域，效果更好（未證實）。

### 步驟 A3：把 SMTP 填進 Supabase

1. 開 Supabase，進入專案。
2. 左側按 **Authentication**，再按 **Emails**，按 **SMTP Settings** 分頁（未證實：Supabase 介面常改版，找不到就用頁面搜尋「SMTP」）。
3. 打開 **Enable Custom SMTP**。
4. 填入上面六項。按 **Save**。
5. 回 **Authentication** → **Rate Limits**（未證實：位置可能不同）。找「電郵寄送次數」那一項。啟用自訂 SMTP 後，預設限額通常仍很低，要手動調高到至少每小時 100（未證實）。按 **Save**。

### 步驟 A4：驗證有效

1. 用一個**沒有登入過的**電郵（可以用 `你的名字+test1@gmail.com`），在 `https://practice.clinicmind-inquire.workers.dev/login` 按「寄登入連結給我」（**Email me a sign-in link**）。
2. 1 分鐘內收到信。看寄件人名稱是你設定的名稱。
3. 檢查「垃圾郵件」資料夾。進了垃圾郵件就在 B 部分之前處理：回服務商頁面，確認網域驗證全部通過。
4. 點信裡的連結。會進入「加入你的班級」頁面（還沒有班級就先停在這裡，這是預期行為）。

**如果信沒有寄來**：到服務商的 **Logs**（Resend）或 **Transactional → Logs**（Brevo，未證實）看有沒有紀錄。有紀錄表示 Supabase 這邊正確，問題在服務商。沒有紀錄表示 Supabase 的 SMTP 設定有誤。把畫面截圖給顧問。**截圖前遮住 Password 欄。**

### 未證實的清單（A 部分）

- 兩個服務的免費額度數字。
- Resend 要驗證網域才能寄給他人。
- Brevo 單一寄件電郵可用，及它的垃圾信風險。
- Supabase 內建電郵的限額不可調。
- Supabase 選單名稱和位置，以及啟用自訂 SMTP 後的預設限額。
- SMTP 的埠號和 Resend 的 Username。

## B. 學生隔離的手動檢查

### 為什麼要做

`docs/HANDOFF.md` 第 3 節：已登入用戶之間的隔離，只有在記憶體內的測試資料庫驗證過，從未在真正的 Supabase 上驗證。4 個端到端測試需要服務金鑰，金鑰留在你手上，所以改用這張核對表。

**這是學生資料的安全關卡。** 任何一步不符，**不要對學生開放**，截圖給顧問。

### 準備

- 需要三個電郵：學生甲、學生乙，加上你的督導電郵。可以用 `你的名字+a@gmail.com`、`你的名字+b@gmail.com`（Gmail 會把這些信都送到同一個收件匣；未證實：Supabase 是否把它們當成不同帳號——預期是不同帳號，步驟 B3 會驗證）。
- 需要兩個互相獨立的瀏覽器空間：一般視窗給學生甲，**無痕視窗**給學生乙，督導用另一個瀏覽器（例如 Safari）。避免登入互相覆蓋。
- 先完成 A 部分，否則登入信可能寄不到。
- 先照 C 部分步驟 C1–C2 建立一個**測試用班級**，名稱寫「測試班」，取得邀請碼。
- **只用虛構內容作答。** 不要貼任何真實個案或學生資料。

### 核對表

每一步都有「預期結果」。不符時：**截圖（含網址列）給顧問，並寫下是哪一步。** 不要自己重試，也不要繼續下一步。

|---|---|---|---|

### 做完之後

- **全部符合預期**：隔離檢查通過。把結果告訴顧問，由顧問更新 `docs/HANDOFF.md`。
- **任何一步不符**：**不要對學生開放。** 把截圖和步驟編號給顧問。
- 清理：測試班和兩個測試學生帳號在對學生開放前要刪除。**目前介面沒有刪除功能**，要在 Supabase 的 SQL Editor 刪，這要顧問給你確切指令。不要自己寫刪除指令。

### 這張表檢查不到的

- 它只測了介面。它沒有直接測資料庫的規則，只是從結果推論。
- 它只用了兩個學生、一個班級。多班級之間的隔離，只用 B16 做了很弱的檢查。
- 它沒有測報告功能（報告功能目前在正式網站是關閉的）。

## C. 開班流程

這一節依現有程式的實際行為寫。

### C1：建立班級

1. 用督導電郵登入。頁首右側會有「督導」連結，按它，或直接開 `/supervisor`。
2. 還沒有班級時，頁面標題是「你的班級」，下面有「建立班級」（**Create a cohort**）表單。已有班級時，按頁面底部的「再建立一個班級」展開表單。
3. 「班級名稱」填名稱（1 至 80 個字元），例如「2027 春季督導班」。
4. 「學期結束日期」按日期欄選日期。**必須是今天之後。**
   - 學生**只能在這個日期之前**加入。日期過了，加入會失敗。
   - 報告在這個日期後保留 90 天（報告功能目前尚未開放）。
5. 按「建立班級」。

預期結果：頁面出現班級名稱、「邀請碼」、「學期結束日期：…」。

如果出現「無法建立班級。請檢查網路連線後再試。」：重新整理再試一次。仍失敗，截圖給顧問。

### C2：取得和發出邀請碼

1. 在班級區塊找到「邀請碼」，後面是 10 個大寫字母和數字（不含容易混淆的 0、O、1、I）。
2. 按「複製邀請碼」，出現「已複製。」。沒有複製成功時，用滑鼠選取代碼手動複製。
3. 把**網址**和**邀請碼**一起發給學生。網址是 `https://practice.clinicmind-inquire.workers.dev`。
4. 只發給本班學生。邀請碼是加入班級的唯一憑證。學生看不到邀請碼，只有督導看得到。

邀請碼的限制（來自程式）：

- 輸入不分大小寫，前後空白會被忽略。
- 同一個帳號在 1 小時內輸入錯誤 10 次，會被鎖 1 小時。提醒學生貼上，不要手打。
- 已加入的帳號再輸入邀請碼，不會換班，也不會改變任何東西。
- 一個班級只有一個邀請碼，目前沒有「重設邀請碼」的按鈕。碼外洩時，建立新班級，並請顧問處理舊班級。

### C3：學生註冊

給學生的步驟（可以直接轉發）：

1. 打開網站網址。網站會帶你到「登入」頁。
2. 輸入你的電郵，按「寄登入連結給我」。
3. 到信箱找信，按信裡的連結。**用同一個瀏覽器開連結。** 信可能在垃圾郵件匣。
4. 在「加入你的班級」頁，「邀請碼」貼上督導給的碼。
5. 「顯示名稱」填 1 至 40 個字元。督導會在你的作答旁看到它。**可以用化名。**
6. 按「加入」。進入首頁，開始學習。

學生常見的狀況：

| 學生看到 | 意思 | 處理 |
|---|---|---|
| 「這個登入連結無法使用，可能已經過期。」 | 連結過期，或換了瀏覽器開 | 回「登入」重新寄一封 |
| 「無法辨認這個邀請碼。請檢查後再試。」 | 邀請碼輸入錯誤 | 重貼，注意空格 |
| 「這個班級已經結束，不再接受新成員。」 | 過了學期結束日期 | 督導建立新班級（見 C1） |
| 「輸入錯誤的邀請碼次數太多。請等一小時後再試。」 | 被鎖 | 等一小時 |
| 一直沒收到信 | 寄信服務問題 | 先查垃圾郵件，再回 A 部分檢查 |

學生在任何時候可以按頁首「登出」。學生在加入之前，在這個瀏覽器已存的進度（本機模式的資料）會在加入後自動移到他的帳號。

### C4：督導開放階段

「階段」是課程的單元（例如基礎階段、EFT 階段）。每個班級各自決定哪些階段開放。

**目前正式網站只有基礎階段，沒有別的階段可以開放。** 班級區塊的「階段」小節會顯示「目前只有基礎階段，沒有可以開放的階段。」這是預期行為。基礎階段永遠對全班開放，不用做任何事。

之後有第二個階段上線時：

1. **先**請專案擁有人在 Supabase 的 SQL Editor 套用 `0004_cohort_stages.sql`（見 `docs/HANDOFF.md` 第 2 節第 4 項）。沒做時，「階段」小節會顯示「暫時無法開放階段。請專案擁有人在 Supabase 套用資料庫更新 0004（cohort_stages）。」
2. 到 `/supervisor`，找到班級區塊的「階段」小節。
3. 每個階段有一個勾選框：「向這個班級開放『階段名稱』」。勾選就是開放；取消勾選就是關閉。勾選後立即儲存。
4. 階段名稱旁若有標記「未審核：學生暫時看不到」，表示該階段的內容還沒審核登記，學生暫時看不到，即使你勾選了。

### C5：督導手動解鎖某一級

學生要在一個模組通過前一級才能做下一級（自評為主）。你可以對單一學生手動解鎖：

1. 在 `/supervisor` 的進度表按學生的顯示名稱。
2. 在「進度」區找按鈕「為『模組名稱』解鎖『等級』」。按下。
3. 之後該處會顯示「『模組名稱』的『等級』是你手動開啟的。」

### C6：日常查看

- 班級頁的進度表：每位學生每個已審核模組的「已完成療程走讀／未完成療程走讀」和「已通過：…」。
- 學生頁的「作答紀錄」：若有「請留意這一筆：…」標記，只是提醒你自己讀回應，不是判定作弊。自評是薄弱的證據。
